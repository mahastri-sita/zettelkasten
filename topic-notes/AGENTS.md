# AGENTS.md

## Scope

These rules apply to `topic-notes/` and all descendants. Inherit the root `AGENTS.md`.

Topic Notes are an AI-maintained semantic index. They are maps and routers, not the main kitchen for substantive thinking.

AI may create and update Topic Notes autonomously.

## Creation Threshold

Create a Topic Note only when the concept is a real router because it:

- recurs across knowledge objects; or
- is necessary to navigate an important Argument and its evidence.

Do not create a Topic Note for every noun, incidental term, single weak connection, or missing filename. When classification between levels is materially ambiguous, do not guess aggressively.

## Content

- Use a canonical, human-readable topic name without an ID or timestamp.
- State the note's scope briefly enough to prevent category drift.
- Use annotated wikilinks: each link must include a short explanation of its epistemic relationship or navigational value.
- Link relevant Arguments, Synthesis Products, Sources, Calculations, Outputs, and other Topic Notes.
- Include only sections that contain useful links. Do not create empty template headings.
- Do not copy substantive reasoning from Argument or mature claims from Synthesis Product.
- Do not turn Topic Notes into literature reviews, glossaries, or independent arguments.

A lightweight structure may include:

```markdown
# Topic Name

## Scope

## Related Topics

## Arguments

## Synthesis Products

## Evidence and Calculations

## Outputs
```

Adapt or omit sections according to actual routing needs.

## Maintenance

- Prefer updating an existing router over creating a near-duplicate.
- Remove or repair stale links when encountered.
- Preserve meaningful cross-field relationships rather than forcing a single-parent hierarchy.
- After substantive work, update only Topic Notes affected by the task.

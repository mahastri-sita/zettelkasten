# AGENTS.md

## Scope

These rules apply to `argument/argument/`. Inherit `argument/AGENTS.md` and the root `AGENTS.md`.

This folder is the main research kitchen. It contains ideas, big questions, research questions, conceptual frameworks, mechanisms, assumptions, speculation, critique, reasoning, and evolving intellectual positions.

## Authority

- Do not create an Argument file without explicit instruction or approval.
- Read, analyze, critique, and test existing Arguments freely when relevant to the user's request.
- Edit an existing Argument only when the user expresses explicit editing intent.
- A research, critique, consistency-check, or evidence-search request alone is read-only for the Argument file.
- When authorized to edit, preserve the user's position and voice. Add challenges or alternatives transparently rather than silently substituting them.

## Form

Argument files are flexible living manuscripts and have no mandatory template or metadata.

- Keep the difference among user position, external evidence, calculation result, AI inference, speculation, counterevidence, and open question intelligible in context.
- Do not force identical headings across files.
- Do not split an Argument because it is long.
- Split only for independent intellectual reuse and only with authority to alter the file structure.
- Preserve unresolved tensions when the evidence does not justify resolution.

## Research Workflow

When testing an Argument:

1. Identify its central question, proposed mechanism, assumptions, and scope.
2. Retrieve context using the root targeted-context order.
3. Find both supporting and disconfirming evidence.
4. Test alternative explanations and scale dependence.
5. Report what survives, what weakens, and what remains speculative.

## Naming

Use a stable, descriptive big question, proposition, framework, or mechanism as the filename. Do not use an ID, timestamp, generic project code, or status taxonomy as the primary name.

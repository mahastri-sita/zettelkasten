# AGENTS.md

## Scope

These rules apply to `output/`. Inherit the root `AGENTS.md`.

Output stores research work that has been expressed as a paper, manuscript, report, article, presentation text, or other communicative product. It is not the main research kitchen.

## Authority

- Do not create an Output without explicit instruction or approval.
- Edit an existing Output only when the user expresses explicit editing intent.
- A request to analyze, review, audit, or critique an Output does not authorize revision.

## Drafts and Final Outputs

Both working drafts and final outputs may live here. Make their status clear in the filename or prominently inside the file without imposing a vault-wide lifecycle system.

Use a stable descriptive title with a light status suffix when needed, for example `Short Title - draft.md` or `Short Title - final.md`. Add version distinctions only when they solve a real identification problem.

## Evidence and Flow

- Derive substantive claims from Argument, with supporting Source and Calculation provenance.
- Do not use Output as a substitute for maintaining the underlying Argument.
- Do not introduce claims that exceed the available evidence merely to improve narrative coherence.
- Preserve citations, qualifications, data limits, and distinctions between finding and interpretation.
- A reusable insight found in an Output may be nominated as a Synthesis Product, but promotion requires user approval.
- Do not back-propagate an Output's wording or position into Argument or Synthesis Product without the applicable authority.

Academic paper drafts default to English. Other outputs follow the user's requested language or the existing file's language.
